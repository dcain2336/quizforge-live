## 2026-10-23 ~14:00 EDT — Stage 3a (build subagent): the Meterless Markovian engine, wired in offline

- **Upstream study:** cloned `Meterless/Meterless` blobless/sparse into `../hidden_files/meterless-upstream` (@1742dec). Key discovery: upstream does NOT ship the engines as runtime libraries — each is an "AGENTS.md-driven implementation spec, not a runtime library" (their words) plus a TypeScript reference implementation meant to be rebuilt in your own stack. All four engines are **Apache-2.0**, so a faithful port with attribution is license-clean.
- **Engine choice: MARKOVIAN.** Why: (1) Fit — the study loop's core problem is exactly the engine's problem: naive planning re-reads a growing history every round (O(n²) context); Markovian bounds each step to goal + a compressed carryover state (O(1) per step). Rounds map 1:1 onto chunks/steps. (2) Lightest — the reference implementation is ~800 lines of zero-dependency TypeScript (config, markers, carryover cascade, prompt builder, efficiency math). H-MEM was rejected: embeddings + sleep-cycle consolidation + knowledge-graph machinery cannot be done honestly in stdlib-only Python. World Model is an entity/fact graph (wrong shape for learner state); Scout Intent is intent routing (not state). (3) The canonical state block (COMPLETED / REMAINING / DECISIONS / CONTEXT) maps directly onto mastered topics / weak topics / strategy decisions / session context.
- **`markovian.py` (NEW):** faithful stdlib port of the reference core — `resolve_config` with upstream BOUNDS + the framing sanity rule (typed `ConfigValidationError`), `estimate_tokens` (ceil(chars/4), labeled "estimated"), the full marker protocol (`parse_markers`/`clean_markers`: [STATE_CHECKPOINT], <CARRYOVER>, [TASK_COMPLETE], NEEDS_TOOL, ...), the four-level `CarryoverService` cascade in upstream's strict order (marker → LLM via injected compressor → heuristic key-phrase extraction → tail truncation; every level budget-checked, truncation guarantees the cap), `canonical_block`, `build_prompt` (chunk 1 = memory + full goal; continuations = truncated goal + [CARRYOVER STATE] + optional [OVERLAP] + marker rules), `run_efficiency` + `projection_curve` (section-6 accounting). Provenance + Apache-2.0 attribution + the honest adaptation list (sync instead of async; History/Progress services not ported — the app is stateless per request and evidence lives in the JSONL logs) are in the file header.
- **`agent.py` integration (the engine is load-bearing, not decorative):** `_engine_plan` folds graded history into per-topic tallies → mastered (correct > missed) vs weak; builds the canonical state; synthesizes a round report ending in [STATE_CHECKPOINT]; runs the cascade (with the Nemotron route as the level-2 compressor when configured, metered like every call). Decisions come from the state: focus = REMAINING topics first (worst gap first, cap 4), difficulty by Markov transition rules (first round easy; weak + accuracy < 0.6 → easy/remediate; accuracy ≥ 0.85 over ≥ 3 attempts → hard; ≥ 0.6 → medium). plan_round returns the engine plan directly when no model route exists; with a route, the model is prompted via `build_prompt` (bounded carryover, never raw history), its reply is marker-parsed (checkpoint kept as `model_checkpoint`), shape-validated, and any failure falls back to the engine plan. Every plan logs a `trace` event and every grade a `telemetry` event (missed topics = the observation that updates REMAINING) into logs/events.jsonl via meterless.log_event.
- **`nemotron.py` env alignment:** documented names are now primary — `METERLESS_BASE_URL` / `METERLESS_RUNTIME_TOKEN` / `METERLESS_MODEL` — with `NIGHTSHIFT_API_URL` / `NIGHTSHIFT_API_KEY` / `NEMOTRON_MODEL` as working fallbacks (all read live at call time). Header updated: the old "assumption" is now the workspace-confirmed shape (OpenAI-compatible, base `http://127.0.0.1:8088/v1`, `/v1/chat/completions`, org "1").
- **Nightshift recon folded in (parent, 2026-10-23):** Nightshift is LOCAL-ONLY — no hosted console, no signup, no cloud endpoint; the Console is a tab in the free local app (Windows / Mac M1–M4) and the runtime token also lands in `<stateDir>/proxy-token`.
